Tool Health Diagnostics

Cross-assembly tool health validator and diagnostics window

Menu: Tools > Natane > Diagnostics Category: Core

Overview

The Tool Health Diagnostics window (NataneToolHealthValidator) validates the health of all editor tools included in the Natane Toon Shader package. It automatically checks whether tools distributed across multiple assemblies are correctly loaded and launchable from menus. The validator comprehensively verifies assembly load status, type existence, and MenuItem attribute presence, displaying causes and remedies when issues are found.

Access

Menu: Tools > Natane > Diagnostics

Features

Comprehensive Tool Checks

  • Assembly Load Verification - Confirms that the three required assemblies (NataneToon.Editor, NataneToon.Editor.Tools, NataneToon.Editor.Migration) are loaded
  • Type Existence Check - Verifies that each tool's class exists within its corresponding assembly
  • MenuItem Attribute Check - Verifies that the [MenuItem] attribute is properly set on tool classes
  • Menu Path Validation - Confirms the validity of menu paths registered in the tool registry

Validated Tools

Validates over 30 tools organized in the following categories:

  • Material Tools - Material Validator, Material Editor, Material Preview, Material Comparison, Makeup Layer Manager
  • Preset Tools - Material Preset Browser, Color Palette Manager, Default Preset Generator
  • Effects Tools - Shadow Wizard, MatCap Composer, Dissolve Generator, Rim Light Visualizer, Screen FX Setup
  • Optimization Tools - Performance Budget, Texture Optimizer, Outline Optimizer, Refraction Balancer, Shader Variant Collector/Stripper, Asset Reference Checker
  • Migration Tools - lilToon Migration, Batch Material Converter, Prefab Variant Converter
  • Mesh Tools - Smooth Normal Baker
  • Others - Dashboard, Help, Particle Effect Editor, VTuber Preset Generator

Diagnostics Results Display

  • Summary Display - Color-coded counts of errors, warnings, and healthy items
  • Problems Only Filter - Toggle "Problems Only" to hide healthy tools
  • Detailed Information - Problematic tools show a cause message and remedy suggestions
  • Re-check - Re-run diagnostics with the "Re-check" button

Validate & Launch API

  • ValidateTool() - Pre-check a single tool by menu path
  • ValidateAndLaunch() - Validate then launch a tool. On failure, displays a dialog with the cause and remedy, offering to open the diagnostics window
  • GetOverallHealth() - Lightweight health check for the Dashboard toolbar indicator (Healthy/Warning/Error)
  • RunFullDiagnostics() - Run comprehensive checks on all registered tools

How to Use

  1. Open "Tools > Natane > Diagnostics" from the menu
  2. The window automatically runs diagnostics on all tools when opened
  3. Review the summary to see error, warning, and healthy counts
  4. Enable "Problems Only" to show only tools with issues
  5. Follow the "Remedy" instructions for each issue to fix problems
  6. After fixing, click "Re-check" to re-run diagnostics and confirm the fix

Severity Levels

  • Error - Critical issue preventing the tool from launching. Assembly not loaded or type not found
  • Warning - The tool exists but has partial issues. MenuItem attribute not found, unregistered in registry, etc.
  • OK - The tool has been successfully validated

Troubleshooting

Assembly Not Loaded

Verify that the corresponding .asmdef file exists and references are correctly configured. Also check the Unity Editor console for compile errors.

Type Not Found

Check whether the class name or namespace has been changed. The ToolRegistry entry must match the actual class's fully-qualified name.

MenuItem Attribute Not Found

Verify that the tool class has a static method with the [MenuItem] attribute. The tool may not be launchable from the menu path without it.

Tips

  • Run diagnostics right after package installation to confirm all tools are loaded correctly
  • The Dashboard toolbar indicator uses GetOverallHealth() for a lightweight check
  • When a tool fails to launch, ValidateAndLaunch() automatically shows the cause
  • When adding new tools, remember to add an entry to the ToolRegistry
