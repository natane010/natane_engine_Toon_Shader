Main Tex Animation

Animate textures with UV scrolling and rotation

Overview

Main Tex Animation applies scroll and rotation animation to the main texture's UV coordinates. Through time-based UV transformation, it enables dynamic effects such as flowing water surfaces, rotating energy fields, and scrolling patterns.

Controlled by the keyword _MAIN_TEX_ANIMATION. When disabled, no shader instructions are generated. Implemented as a local keyword (shader_feature_local).

Parameters

Enable Main Tex Animation _MainTexAnimation toggle

Toggles the Main Tex Animation feature on/off. Branches at compile time using the keyword _MAIN_TEX_ANIMATION.

Default: OFF

Scroll Speed XY _MainTexScrollSpeed vector

Specifies the UV scroll speed in the X and Y directions. Each component corresponds to the UV offset per second. The X component controls horizontal scrolling and the Y component controls vertical scrolling. When both scroll speeds are near zero (squared sum below epsilon), the scroll computation is automatically skipped.

Default: (0, 0, 0, 0)

For water flow use (0.1, 0); for diagonal scrolling use (0.05, 0.05).
Rotate Speed _MainTexRotateSpeed float

Specifies the rotation speed of the main texture. The UV is rotated around the center point (0.5, 0.5) using time-based sin/cos transformation. Positive values rotate counter-clockwise, negative values rotate clockwise. When the rotation speed is near zero (absolute value below epsilon), the rotation computation is automatically skipped.

Default: 0

For a gentle rotation, values around 0.1–0.3 work well.

Usage Tips

  • Scrolling and rotation can be used simultaneously. Combining them enables complex motion effects
  • The UV transformation is applied at the very beginning of the fragment shader, so it affects all subsequent processing after main texture sampling
  • Particularly suited for effect materials such as energy, magic circles, and water surfaces
  • Can be combined with VRChat animation parameters to dynamically control scroll speed
  • When speed values are zero, the computation is skipped, so setting unused directions to zero has no performance cost
