# ステンシル・プリセット（髪から目が見える / See Through Hair 相当）

前髪より前に眉・目・まつげを描き、2Dイラストのような「髪から目が見える」ルックを作る。

ツール: `Tools > Natane > エフェクト Effects > ステンシルプリセット Stencil Preset`

---

## 1. なぜツールが要るのか

ステンシルのプロパティ（`_StencilRef` / `_StencilComp` / `_StencilOp` / `_StencilFail` /
`_StencilZFail` / `_StencilReadMask` / `_StencilWriteMask`）は**以前から本体シェーダーに存在していた**。
足りなかったのは「どの値をどう組み合わせるか」という知識と、参照値の割り当て作業。

つまり**機構はあるがワークフローが無い**状態で、これが採用障壁になっていた。
2026年3月に公開された See Through Hair（goorm）が Modular Avatar 対応で話題になったが、
対応シェーダーは Poiyomi Toon と lilToon のみで本パッケージは対象外だった。

## 2. 3つの役割

| ロール | 対象 | Stencil 設定 | Queue |
|---|---|---|---|
| **Writer** | 眉・目・まつげ | `Ref = N` / `Comp = Always(8)` / `Pass = Replace(2)` | `1990`（Geometry より前） |
| **Cutter（完全透過）** | 前髪 | `Ref = N` / `Comp = NotEqual(6)` / `Pass = Keep(0)` | 既定のまま |
| **Cutter（半透明）** | 前髪 | 上と同じ + アルファを下げる | `3000` 以上 |

「完全透過」と「半透明」を分けているのは、**眉は完全に透かし、前髪は薄く残す**という
使い分けが定番だから。

### 動作原理

1. Writer（眉・目）が**先に**描かれ、その画素のステンシルバッファに `N` を書き込む
2. Cutter（前髪）は「ステンシルが `N` **でない**画素にだけ描く」ので、
   眉・目が描かれた領域には髪が描かれない
3. 結果として、前髪の下から眉・目が見える

**Writer の Queue を前に出すのが必須。** 髪が先に描かれてしまうと、
ステンシルを読む相手がまだ存在しないため何も起きない。

## 3. 使い方

1. アバターのルートを指定する（配下の Renderer が一覧される）
2. 参照値を決める。「未使用値を探す」でプロジェクト内の衝突を避けた値が入る
3. 各 Renderer にロールを割り当てる（名前から自動推測される。眉/目 → Writer、髪 → Cutter）
4. 「描画順の差分」で、適用前後の Queue の変化を確認する
5. 「ステンシル設定を適用」

解除は「ステンシルを解除」。参照値を 0、比較を Always、Queue をシェーダー既定へ戻す。

すべて `Undo.RecordObject` を通しているので Ctrl+Z で戻せる。

## 4. 参照値の衝突について

⚠ **VRChat では他アバターのステンシルと衝突しうる。**

ステンシルバッファはカメラ単位で共有されるため、他のアバターが同じ参照値を使っていると
互いの見た目を壊す可能性がある。

- ツールはプロジェクト内のマテリアルを走査して使用中の値を検出し、未使用値を提案する
- 提案は **32 以上**から探す。1〜10 は誰もが最初に選ぶ値で衝突しやすいため
- ただし**他アバターとの衝突までは検出できない**。ワールドで問題が出たら値を変えること

## 5. Fake Shadow との併用

[Fake Shadow](FAKE_SHADOW.md)（前髪の落ち影）と併用する場合、
**落ち影が眉の上に乗ると破綻する**。

Fake Shadow 側のマテリアルにも同じ参照値を設定し、
`Comp = Equal` で「顔が書いた領域のみ」に限定する。
Fake Shadow 設定ツールの「ステンシルで顔の中に限定」で設定できる。

## 6. Material Validator の検出

`Tools > Natane > マテリアル Material > マテリアル検証` に、
**Writer と Cutter の片方だけが存在する状態**の検出を追加してある。

| 状態 | 見た目 |
|---|---|
| Writer だけ | 眉・目が単に手前に描かれるだけ。透過にならない |
| Cutter だけ | くり抜く領域が存在せず、何も起きない |

どちらも「設定したのに変わらない」という分かりにくい失敗になるため、明示的に警告する。

## 7. 制限

- **不透明バリアントでは「半透明カッター」のアルファが効かない。**
  Transparent 系バリアントへ切り替えてから使うこと
- Writer の Queue を前に出すと不透明のソート順が変わるため、
  他の不透明マテリアルとの前後関係が変わることがある。適用前に差分を確認すること
- ステンシルは**カメラ単位**。鏡（Mirror）の中でも同じ挙動になるが、
  ワールド側のポストプロセスがステンシルを使っている場合は干渉しうる
